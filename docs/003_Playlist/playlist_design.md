=================================================================
プレイリスト画面設計（データ更新トリガー）
=================================================================
※本書は当面、プレイリスト表示時のデータ更新呼び出しを定義する。
※列・抽出・並び替え等は別ドキュメント／後続で追記する。
※日足・気配値の取得ロジック本体は 01_Data_Layer.md【DailyBarService】を正とする。
※監視銘柄（user_watchlist）とプレイリストの関係は 00_Master_Design.md 3-E を正とする。


-----------------------------------------------------------------
1. この画面でやること（データ更新）
-----------------------------------------------------------------
【きっかけ】
・サイドバー等でプレイリストを選んだとき
・プレイリストを切り替えたとき
・リンク等でプレイリスト画面に遷移したとき

【対象】
・user_watchlist 全体（いま表示中のプレイリストの中身だけではない）
  - 日足更新も気配値更新も、対象は監視銘柄名簿（user_watchlist）
  - プレイリストは見せ方の箱（00_Master_Design 3-E）

【呼び出す処理（順）】
  1. DailyBarService.update_daily_bars_for_watchlist(...)   … 日足
  2. DailyBarService.update_snapshots_for_watchlist(...)  … 気配値

【前提】
・スキップ判定あり（確定日足が揃っている／同一時間枠内の気配値済みは fetch しない）
・定時の強制一括取得はしない


-----------------------------------------------------------------
2. アプリ起動との関係
-----------------------------------------------------------------
・アプリ起動時の更新は 01_Data_Layer.md の〈UIトリガー〉を正とする
  （起動時：日足一括 → 気配値一括 → cleanup_stale_viewed_symbols）
・プレイリスト表示／切替／リンク遷移では cleanup は呼ばない（起動時のみ）


-----------------------------------------------------------------
3. やらないこと（この画面の更新では）
-----------------------------------------------------------------
・indicators の一括計算（デッキ表示側）
・touch_last_viewed（個別チャート側）
・「表示中プレイリストの銘柄だけ」を更新対象にする
  （更新対象は常に user_watchlist 全体）
