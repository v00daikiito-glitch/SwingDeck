=================================================================
個別チャート画面設計（データ更新トリガー）
=================================================================
※日足・気配値の取得は 01_Data_Layer.md【DailyBarService】を正とする。
※監視・Hold・一時閲覧は 00_Master_Design.md 3-E および 01_Data_Layer.md【一時閲覧銘柄】を正とする。
※チャート見た目の詳細は後続で追記する。


-----------------------------------------------------------------
1. ケースA：個別チャート画面を開いたとき
-----------------------------------------------------------------
【きっかけ】
・サイドメニューやリンク等で個別チャート画面を開いたとき

【表示銘柄】
・リンク等で指定があればそれ
・無ければ前回この画面で最後に見ていた銘柄
・それも無ければ空状態（チャートは出さない）

【その後】
・銘柄が決まっていれば「3. 共通手順」へ


-----------------------------------------------------------------
2. ケースB：この画面で銘柄を選んだ／切り替えたとき
-----------------------------------------------------------------
【きっかけ】
・個別チャート画面の検索等で銘柄を選んだ／切り替えたとき

【表示銘柄】
・ユーザーが選んだ銘柄
・検索は SearchService.search
・未登録なら 01_Data_Layer.md「1. 全体方針」の流れ 1〜9 で symbols / search_cache を整える
  （すでに symbols にあれば、流れの5のあと 6〜9 は省略可）
・その後「3. 共通手順」へ（全体方針の10に相当）


-----------------------------------------------------------------
3. 共通手順（更新が先、描画は後）
-----------------------------------------------------------------
対象：表示中の1銘柄（監視外の一時閲覧も含みうる）

  1. DailyBarService.update_daily_bars(symbol_id)  … 日足を揃える
  2. DailyBarService.update_snapshot(symbol_id)  … 気配値を揃える
  3. SymbolMasterService.touch_last_viewed(symbol_id)
  4. user_watchlist と Hold の有無を見てボタン表示を決める
     （例：「監視銘柄に登録」／「監視中」、「Hold に登録」／「保有中」。文言は後で可）
  5. indicators を計算する
  6. チャートを描画する

・1〜2 はスキップ判定あり（揃っていれば fetch しない）
・古い足のまま先に描画しない


-----------------------------------------------------------------
4. 登録ボタン
-----------------------------------------------------------------
・「監視銘柄に登録」→ user_watchlist に追加だけ（Hold には入れない）
・「Hold に登録」→ Hold に入り、未登録なら user_watchlist にも追加
・副作用の詳細は 00_Master_Design.md 3-E


-----------------------------------------------------------------
5. やらないこと
-----------------------------------------------------------------
・update_*_for_watchlist（監視全体の一括更新はしない）
・cleanup_stale_viewed_symbols（アプリ起動時のみ）
