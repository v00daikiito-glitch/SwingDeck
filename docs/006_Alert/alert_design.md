03_Alert_Design（アラート機能 設計書）
=================================================================






1. 基本方針
-----------------------------------------------------------------
・アラートの種類による挙動の違いは一切出さない（価格固定でもMAでも乖離率でも同じ体験にする）
・アプリを閉じていてもアラートが機能することを最優先とする
・最初から価格固定・MA系・乖離率系すべて対応する
・サーバー側は最初からEODHDまたはJ-Quantsの個人有料プランを使用する（Yahoo無料はサーバーでは使用しない）
・デバイス側はチャート・フィルター・バックテストなどの重い処理を担当
・サーバーはアラート監視と通知のみを担当（最小限に保つ）


2. 対応するアラートの種類
-----------------------------------------------------------------
最初から以下すべて対応する。

・価格固定アラート（指定価格を上回る / 下回る）
・MA系アラート（SMA/EMAのタッチ、クロス、ゴールデンクロスなど）
・乖離率アラート（指定期間のMAからの乖離率が±X%を超えたら）

アラート条件は params_json で柔軟に保持する。これにより将来的な拡張も容易にする。


3. サーバー側処理の全体フロー
-----------------------------------------------------------------
市場クローズ後の一括処理だけに頼らず、以下のハイブリッド方式とする。

・価格固定アラート：15〜60分に1回、気配値（最新足）を取得して条件チェック
・MA系・乖離率系アラート：毎日1回（市場クローズ後）に日足ベースで指標を再計算して条件チェック
　（気配値で「今どれだけ近づいているか」の簡易チェックは15〜60分ごとに行う）

処理の流れ：
1. ユーザーがデバイスでアラートを設定 → サーバーに同期
2. 定期ジョブで該当銘柄のデータを取得
3. 条件に合致したら通知を送信
4. 通知済みフラグを更新（重複通知防止）

これにより、アプリを閉じていてもアラートが動作する。


4. データベース設計（サーバー側）
-----------------------------------------------------------------
alerts テーブル

| カラム名          | 型       | 内容                                       |
|-------------------|----------|--------------------------------------------|
| id                | int      | 主キー                                     |
| user_id           | string   | ユーザー識別                               |
| symbol_id         | string   | 銘柄コード                                 |
| alert_type        | string   | 種類（price_above, ma_touch, deviation など） |
| params_json       | text     | 詳細パラメータ（期間、しきい値など）       |
| is_active         | bool     | 有効/無効                                  |
| last_triggered_at | datetime | 最後に通知した日時                         |
| created_at        | datetime | 作成日時                                   |

params_json で条件を柔軟に表現する。



#### params_json の例

価格固定アラートの場合：
```json
{
  "direction": "above",          // "above" or "below"
  "target_price": 1850.5
}
```

MAタッチの場合：
```json
{
  "ma_type": "sma",              // "sma" or "ema"
  "period": 25,
  "condition": "touch"           // "touch" / "cross_up" / "cross_down"
}
```

乖離率アラートの場合：
```json
{
  "ma_type": "sma",
  "period": 25,
  "threshold_percent": 5.0,      // ±5%
  "direction": "both"            // "above" / "below" / "both"
}
```

#### デバイス → サーバー同期時のJSON例

アラートを新規作成・更新するときに送る形式：

```json
{
  "user_id": "user_abc123",
  "symbol_id": "7203.T",
  "alert_type": "price_above",
  "params_json": {
    "direction": "above",
    "target_price": 1850.5
  },
  "is_active": true
}
```

5. データ取得戦略（サーバー側）
-----------------------------------------------------------------
・最初から EODHD個人有料プラン または J-Quants個人有料プラン を使用
・アラートが有効になっている銘柄のみを対象にする
・気配値（最新足）取得が可能なプランを選択する
・取得頻度：
  - 価格固定アラート：15〜60分ごと
  - MA/乖離率系：毎日1回（気配値での簡易チェックは15〜60分ごと）


6. 通知方法
-----------------------------------------------------------------
・メイン：メール通知
・将来的に追加：プッシュ通知（FCM）
・通知内容はシンプルにする（銘柄・条件・現在値・トリガー時刻）

#### 通知メールの内容例

件名：
【SwingDeck アラート】7203.T が条件に到達しました

本文：
銘柄　　：7203.T（トヨタ自動車）
条件　　：価格が 1850.5 円を上回りました
現在値　：1862.0 円
発生時刻：2026-07-26 15:02:11 JST

※銘柄名は symbols テーブルから参照する。
このメールは自動送信です。


7. プランによるアラート数制限
-----------------------------------------------------------------
アラート数に上限を設ける。

・無料 / ベーシック：10〜20個
・有料スタンダード：100個
・プレミアム：無制限または500個

これによりサーバー負荷をコントロールし、収益化の差別化にもなる。


8. サーバー計算の負荷について
-----------------------------------------------------------------
デバイス側で計算しているロジックをサーバーで実行するだけなので、負荷はそれほど高くない。

・対象はアラート設定されている銘柄のみ
・毎日または15〜60分に1回の処理
・同じ銘柄に複数アラートがある場合はデータ取得を1回にまとめる

初期ユーザー数では問題になりにくい。将来的にユーザー数が増えた時点で最適化（キャッシュ、並列処理など）を検討すれば十分対応可能。


9. リスクと注意点
-----------------------------------------------------------------
・EODHD/J-Quantsの個人有料プランをサーバーで使用するのはグレーゾーンである
・ユーザー数が増加したら、早めに商用ライセンスへの移行を検討する
・気配値取得が可能なプランを契約時に確認する
