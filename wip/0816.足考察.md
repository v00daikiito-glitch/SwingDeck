## 全体の流れ（骨組み案・修正版）

価格更新ボタンなどで「足作成サービス（仮名）」が動くイメージ。

1. トリガー発生（ユーザーがアプリ等を開く／価格更新ボタン。1サイクルにつき1回まで）
2. 対象銘柄の最新データを取得する
3. 取得したデータを `latest_snapshots` に書き込む
4. その日の日足が「確定」したかどうかを判定する  
   - 確定していれば：  
     5. その日のデータを `daily_bars` へ書き込む  
     6. `daily_bars` を元に `weekly_bars` を更新する  
     7. `daily_bars` を元に `monthly_bars` を更新する  
     8. 6・7が両方エラーなく終わったら、対象日の `latest_snapshots` の行を削除する  
   - 確定していなければ：5〜8はスキップ
9. **（4の結果に関係なく、毎サイクル必ず）** その時点の材料から `daily_bars_all` / `weekly_bars_all` / `monthly_bars_all` を組み立て直す  
   ※今夜合意：ここは実体テーブルにせず、その場計算／ビュー。名前は同じ

## 用語（wipパック基準）

| 用語 | 意味 | 元テーブル |
| --- | --- | --- |
| `bar_close` | 確定足の終値 | `daily_bars`（`adj_close`） |
| `current_price` | 評価用のいま値。気配優先、無ければ最新 `bar_close` | `latest_snapshots.last_price` → 無ければ `daily_bars` |
| `calculate_current_price` | `current_price` を返す関数 | Catalog kind: `"current_price"` |

## テーブル（wipパック基準）

| テーブル | 役割 | 更新頻度（当時の理解） |
| --- | --- | --- |
| `daily_bars` | 確定日足（不変） | 日足確定時のみ |
| `latest_snapshots` | 今日の気配（可変） | 市場が開いている間、随時 |
| `weekly_bars` | 確定週足＋進行中週足 | 日足確定ごと |
| `monthly_bars` | 確定月足＋進行中月足 | 日足確定ごと |
| `daily_bars_all` | 全関数・チャートが読む日足の窓口（確定＋最新を合成） | 毎サイクル（実体にしない） |
| `weekly_bars_all` | 同上（週足） | 毎サイクル（実体にしない） |
| `monthly_bars_all` | 同上（月足） | 毎サイクル（実体にしない） |

`latest_snapshots` の削除順：`daily_bars` 確定 → `weekly_bars`・`monthly_bars` 更新（両方成功後）→ 対象日の snapshot 行を削除。

## Adapter（取得だけ。DBに書かない）

- `fetch_daily_bars(symbol_id, ...)` → 確定日足を共通形で返す
- `fetch_snapshot(symbol_id)` → 今日の気配を共通形で返す

## Service（取得〜保存。★＝まだ名前が無い／これから作るもの）

**すでに名前があるもの（`01_Data_Layer.md`）**

- `update_daily_bars(symbol_id, ...)`
- `update_daily_bars_for_watchlist(...)`
- `update_snapshot(symbol_id)`
- `update_snapshots_for_watchlist(...)`

**これから作る／名前未定（★）**

- ★ `weekly_bars` / `monthly_bars` を更新する関数（まだ名前なし）
- ★ `daily_bars_all` / `weekly_bars_all` / `monthly_bars_all` を組み立てる関数（まだ名前なし）  
  ※今夜合意後は「組み立てて返す窓口」でよく、実体へ upsert する必要はない
- ★ 「足作成サービス（仮名）」本体：価格更新ボタンで起動し、上の流れを1銘柄（例：任天堂）についてまとめて回す係

## スキップ判定（Data Layer 基準）

- 日足：最新 `trade_date` と「想定される最新の確定営業日」を比較。揃っていればスキップ  
  ※この「想定される最新…」の定義は薄い → 祝日カレンダーなし／Adapterに聞いて実在分だけ信じる、方向で後続議論あり
- 気配値：時間枠を決め、`updated_at` が枠内ならスキップ
